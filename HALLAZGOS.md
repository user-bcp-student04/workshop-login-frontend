# Hallazgos del frontend ReqFlow

Los contratos de flujo observados que deben preservarse están descritos en [docs/ENDPOINTS.md](docs/ENDPOINTS.md). Las afirmaciones de CVE y duplicación se distinguen como no confirmadas cuando no hay evidencia suficiente.

| id | hallazgo | tipo | explicacion | evidencia (archivo:linea) | severidad | estado |
|---|---|---|---|---|---|---|
| H-01 | Token de sesión almacenado en `localStorage` | Vulnerabilidad | El token queda accesible desde JavaScript del mismo origen; si ocurre una ejecución de script no confiable, podría leerse y reutilizarse. No se afirma que exista un XSS confirmado en este hallazgo. | `src/app/login/login.component.ts:47`; `src/app/dashboard/dashboard.component.ts:36` | alta | Pendiente |
| H-02 | Mensaje dinámico renderizado con `[innerHTML]` | Vulnerabilidad | El mensaje combina HTML con el usuario y el error recibido. Angular sanitiza el binding, por lo que aquí no se confirma un bypass ni ejecución de script; sí existe una superficie de marcado dinámico que puede evitarse. | `src/app/login/login.component.ts:55-56`; `src/app/login/login.component.html:39` | media | Pendiente |
| H-03 | Los componentes concentran HTTP, URLs, sesión y navegación | Refactor | Login y dashboard conocen endpoints y llaman Axios directamente; también leen/escriben sesión y navegan. Cambiar el transporte o el flujo obliga a modificar componentes y aumenta el acoplamiento. | `src/app/login/login.component.ts:41-50`; `src/app/dashboard/dashboard.component.ts:36-44`; `src/app/dashboard/dashboard.component.ts:74-77` | media | Pendiente |
| H-04 | No hay pruebas del flujo de autenticación y dashboard | Bug | La única spec encontrada cubre el formato de una etiqueta; no hay pruebas localizadas para login, persistencia, consulta de tareas ni logout, así que regresiones de esos contratos pueden pasar inadvertidas. | `src/app/utils/legacy-format.spec.ts:4-6`; `vitest.config.ts:6`; inventario: `Get-ChildItem src -Filter *.spec.ts -File -Recurse` encontró solo esa spec | media | Pendiente |
| H-05 | Uso de `any` y condicionales anidados | Refactor | `any` reduce la comprobación estática de datos de login/tareas y `login()` anida validaciones, dificultando cambios seguros. | `src/app/login/login.component.ts:16-20`; `src/app/login/login.component.ts:33-46`; `src/app/dashboard/dashboard.component.ts:23-27`; `src/app/utils/legacy-format.ts:1` | baja | Pendiente |
| H-06 | Duplicación de lógica | Refactor | No se identificó un bloque de lógica duplicado entre los componentes examinados; no se afirma este hallazgo sin evidencia concreta. | No encontrado en `src/app/login/login.component.ts`, `src/app/dashboard/dashboard.component.ts` y `src/app/utils/legacy-format.ts`. | baja | No encontrado |
| H-07 | Versiones de dependencias listadas; CVE específico no confirmado | Sugerencia | `axios` y `lodash` están fijados a las versiones indicadas por RETO, pero no se confirma un CVE en este análisis: `npm audit --audit-level=moderate` terminó con `ENOLOCK` porque no hay lockfile. Se requiere lockfile y revisión de advisories antes de elevarlo a vulnerabilidad confirmada. | `package.json:19` (`axios`); `package.json:20` (`lodash`); comando `npm audit --audit-level=moderate` -> `ENOLOCK` | baja | Pendiente |
